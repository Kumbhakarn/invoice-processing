# Invoice evaluation dataset

This directory contains ten synthetic invoice examples and their manually authored
expected extraction values. No customer documents or personal data are included.
Each expected JSON file was checked against its paired source text; it was not
generated by an extraction model.

## Layout

- `invoices/` contains UTF-8 plain-text source invoices. Filenames are stable IDs.
- `expected/` contains one JSON object per invoice, using the current backend
  extraction field names. Missing or unstated values are `null`.

Add new examples as matching `id.txt` and `id.json` files. Keep IDs unique and
update this guide when adding formats or limitations. A pytest check ensures that
both directories have identical ID sets and that each expected file is valid JSON.

## Coverage

The set varies vendor identity and layout, commercial and export invoices,
line-item count, omitted fields, currencies (USD, EUR, GBP, JPY, CAD, AUD, INR,
AED, SGD, and CHF), date notation, and address formatting. `inv-08` is an
OCR-style transcription of a synthetic low-quality scan: the source explicitly
marks illegible text and omitted values.

## Supported formats and limits

The evaluation fixtures are plain-text transcriptions, not upload-ready PDF,
JPEG, or PNG documents. They validate expected field annotations and dataset
pairing; they do not measure OCR, layout recognition, image quality handling, or
binary upload validation. In particular, the OCR-style fixture is not a scanned
image. All amounts and examples are illustrative and do not define tax,
accounting, or currency-conversion rules. The dataset is small and synthetic,
so it does not represent the full diversity of production invoices.
